## The free tools that already took the screenshot

**Windows: Snipping Tool.** Press Win + Shift + S, take the capture, click the notification, and the editor opens with a pen, a highlighter, shapes, a text tool, a ruler and an eraser ([Microsoft's guide](https://support.microsoft.com/en-us/windows/open-snipping-tool-and-take-a-screenshot-a35ac9ff-4a58-24c9-3253-f12bac9f9d44)). Save or copy. On raw speed nothing beats it.

**macOS: Markup.** After a screenshot, click the thumbnail in the corner before it fades and Markup opens on it directly. For a file already saved, open it in Preview and click the Markup button: pen, shapes, text, highlighter, colour picker.

**iPhone and iPad: Markup.** Tap the screenshot preview and the same pen and shape tools appear, with the bonus that a full-page web screenshot can be captured and marked up in one pass.

Free, no account, and all three write the marks into the image.

## Where a marked-up file runs out

The output of every tool above is a PNG, and a PNG has no idea it is part of a conversation.

Replies detach: your arrow points at a button, their answer is a chat message somewhere below the image. Versions fork: they annotate your annotated screenshot and send it back, so now there are two and one of them is stale. Nothing is pinned, so "the spacing under the header" means re-finding the spot every time someone reads the thread. Two rounds in, the image in the thread and the image somebody is looking at are not the same image.

For one arrow sent once, none of that matters. For a design review, a bug report, a proof or a client sign-off, all of it does.

## Annotating an image as a shared page

1. Open [marklayer.app](https://marklayer.app) and drop the image on it. PNG, JPEG, GIF, WebP or AVIF, up to 25MB. Or paste the URL of an image already online and skip the upload.
2. Mark it up: arrows, freehand, boxes and circles, a text label, an area capture with a note, or a comment pinned to an exact point.
3. Press Share.
4. They open the link in a browser, with no account and no install, and reply under your comments or add their own. If you are both in it at once, the cursors move.

Each mark records where it sat on the image rather than where it sat on your screen, so it stays on the right pixel when the window changes size or the link is opened on a different display.

## Which route fits which job

| What you're doing | Use |
| --- | --- |
| One arrow on a screenshot, sent once | Snipping Tool or Markup. Fastest, and it saves to the file |
| An image you need as a flattened file | Snipping Tool, Markup or Preview, same reason |
| A mockup or proof someone has to sign off on | A link-based annotator, so approval and questions stay on the image |
| A bug screenshot a developer will ask about | A link, so the follow-up question lands on the pixel |
| A chart or diagram a group is discussing | A link, so replies thread instead of scattering through chat |

## The honest limits

No annotated image comes out, because the marks live in the link and not in the file.

No text highlights on an image, since there is no text layer to bind one to. A PDF with real text behaves differently, which is covered in [how to annotate a PDF](/guides/how-to-annotate-a-pdf).

The element inspector, measure and multi-select are hidden, because they read a page's HTML and an image has none.

Uploads cap at 25MB, and the file is deleted 90 days after the last time the link was opened.

Annotating is desktop only. Opening a shared link to read works anywhere.
