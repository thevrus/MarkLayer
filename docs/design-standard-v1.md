# MarkLayer UI 设计与交付标准 v1.0

生效日期：2026-11-11。适用范围：MarkLayer 房间及其相关产品 UI；营销页面和被标注的外部网页有自己的样式，不强行套用。本标准固定设计方向和交付规则；数值基线按 2026-11-11 的仓库 `d3d62e8` 源码取证，不声称所有现有界面已统一或通过视觉验收。

## 1. 设计原则与真源

延续现有风格：暖中性色、紧凑工具栏、亮暗主题、低装饰性浮层、图标工具的反色选中态。Figma 是可编辑设计交付的真源；现有实现的数值基线以以下代码为准。设计改动须单独记录、确认后再同步代码与 Figma，不以截图或此文复制的数值覆盖源码。

| 来源 | 职责 |
| --- | --- |
| `packages/tokens/theme.css` | 共享浅色基础 token 与字号 |
| `apps/worker/web/style.css` | Web 主题、深色覆盖、Geist 色阶及 Web 字体 |
| `apps/extension/entrypoints/content/style.css` | 扩展主题与深色覆盖 |
| `apps/extension/lib/geist.ts` | 控件、图标、浮层与状态的实现配方 |
| `apps/extension/components/Toolbar.tsx` | 实际工具栏组合、位置与交互 |

## 2. 源码核实的参考值

颜色按用途绑定变量，不把应用背景和控件表面当作同一个 token。下表为 Web 默认上下文；页面和设备容器可能另有覆盖。

| 用途 / 建议 Figma 变量 | 源码变量 | 浅色 | 深色 |
| --- | --- | --- | --- |
| `color/surface/app` | `--color-ml-bg` | `#fbfaf9` | `#111110` |
| `color/text/app` | `--color-ml-fg` | `#1a1a1a` | `#e8e5e0` |
| `color/control/button` | `--color-ml-btn` | `#1a1a1a` | `#e8e5e0` |
| `color/control/button-text` | `--color-ml-btn-fg` | `#fff` | `#111` |
| `color/accent` | `--color-ml-accent` | `oklch(0.65 0.15 300)` | `oklch(0.78 0.13 300)` |
| `color/control/surface` | `--ds-background-100` | `#fff` | `#000` |
| `color/control/strong` | `--ds-gray-1000` | `#171717` | `#ededed` |
| `color/control/focus` | `--ds-focus-color` | `#0070f7` | `#50a8ff` |

这些 Figma 名称是对照建议，并非已建成的 Variables；OKLCH 转换后的观感需在 Figma 实测。Web 落地页另有 `#fff` / `#171717` 覆盖，不能因此声称所有页面色值相同。

共享 UI 字号依次为 `micro` 10、`mini` 11、`meta` 12、`ui` 13、`uiLg` 14、`body` 15 px（按 16px 根字号换算）。它们不覆盖页面标题等其他专用字阶。Web 使用 Geist 和回退字体，扩展字体栈优先系统字体；字体安装与授权由设计师确认。

工具栏图标控件为 32px，图标 16px、描边 1.5；面板紧凑控件 28px，字段内小控件 24px。工具栏外壳 12px 圆角、4px 内边距，内部常用控件 8px 圆角。控件默认灰色图标、悬停使用灰色透明底、选中使用 `--ds-gray-1000` 底与 `--ds-background-100` 前景；键盘焦点采用 2px 焦点环、1px 偏移。分段选择器使用另一种凸起选中样式，不能概括为所有选中态都反色。

浮层沿用 `geist.ts` 的 `surface` 与对应 `--ds-shadow-menu`；Tooltip 使用独立阴影。项目有减少动效处理，新的交互应提供等效静态状态。组件尺寸、阴影、字体及响应式设计需对照实际使用场景，不将示意图中的推测值当作通用规范。

## 3. 设计交付契约

1. 主要交付可访问且可编辑的 Figma 链接或 `.fig` 文件：文字、图标、页面和组件可分别选取编辑，不能整页扁平化为截图。交付时明确链接访问方式；截图、HTML 和说明文档仅为辅助。
2. 按本次需求覆盖受影响页面、相关组件、必要状态和流程，不要求每个工具图标单独出页。组件优先复用；新增组件标记名称、用途、所属区域和关联项。
3. 使用可复用组件、适用的变体、Auto Layout 和 Variables；提供亮暗主题及对应需要的状态。Figma 与代码变量或组件的映射填写到交付清单，尚未建立的标为待补。
4. 稳定语义 ID 与外观分离。已有 ID 沿用，新增 ID 在清单中提出，不根据图标外观或图层位置推断。Figma 记录视觉与交互，功能语义、权限、事件和未来 AI 动态组件协议另行定义；Figma 不是可执行协议。
5. 填写 [交付模板](design-handoff-template.md)：范围、页面、组件、状态、资源、差异、未决项与访问方式。新样式须写理由、对照基线和待确认状态，不直接改写基线。

## 4. 验收与版本管理

验收人打开交付文件，实际选择并编辑页面文字、图标、组件和变体；检查本次范围、亮暗模式、必要交互状态、变量绑定及组件复用，核对字体和资源许可、语义 ID、例外和未决项。实际检查后才标记通过；不可访问或无法编辑即退回补齐。Figma 文件未创建或未检查时，不能宣称已完成 Figma 验收。

视觉基线或交付契约修改须更新本文版本、日期和变更说明，并同时记录代码与 Figma 同步状态。纯新增未确认设计先登记，不修改已确认基线。现有交付包的冲突和待确认内容见 [核对记录](design-package-reconciliation.md)。
