- `apps/extension/lib/viewport-reader.ts:12` 定义条目：标签、角色、名称及来源/截断标记、复用现有稳定选择器、元素尺寸、视口内可见交集和现有六项关键计算样式。坐标均为当前文档 viewport CSS px，不混用 DPR。
- `apps/extension/lib/viewport-reader.ts:226` 的 `createViewportReader(document).readNext()` 为显式调用入口：默认每批最多 20 条、最多访问 200 个结构节点；没有全页元素列表或 HTML 序列化，没有新增定时器、observer 或监听器。惰性游标只在请求时前进，跳过隐藏/不可访问和扩展自有子树，离屏节点不提取名称/条目。不可安全剪枝的离屏容器仍可能逐批经过，以免漏掉溢出到视口的后代；预算耗尽可返回空批次，必须看 `done` 判断结束。
- `apps/extension/components/InspectorLayer.tsx:694` 接入扩展面板的手动读取与复制；复用 `secondaryBtn` 及现有 `px-4 pb-3`，没有新增颜色、字号或间距值。网页 Viewer 沿用原有单元素 inspect，不提供此入口，避免误读外层应用。
- 测试证据：`apps/extension/lib/viewport-reader.test.ts` 的「复杂 DOM 输出角色、常见可访问名、稳定选择器、视口裁剪和关键样式」「隐藏、ARIA 隐藏、inert、透明和扩展自有子树不会被读取」「超出视口和滚动容器裁剪区域的元素不产出，部分可见区域按交集报告」「iframe 仅报告边界，不访问同源或跨源内部文档，也不泄露 src」「长页面按需分批，创建和等待均不读取，预算耗尽可返回未结束的空批次」；另覆盖游标重置、隐藏根节点、名称截断及输入值不外泄。
- 入口回归：`apps/extension/lib/selected-panel.test.ts` 的「扩展检查面板只在点击入口时读取一批，复制失败重试同批；共享 Viewer 不出现入口」验证 20 条/下一批、无重复和失败重试。
- **真实 Edge 证据（2026-11-11）：** 固定复用 PID 23204、验收目录 `.edge-profile`、CDP 9336 的有窗口 Edge 157.0.4341.42；通过 `Extensions.loadUnpacked` 加载实际源码构建的扩展 0.11.0，在 Inspect 面板用 `Input.dispatchMouseEvent` 点击真实「读取视口下一批」按钮。未使用 headless、DOM 模拟或重画的面板。截图由 `Page.captureScreenshot` 获取该 Edge 的真实页面渲染；窗口工具不可用后，按用户明确授权改用此路径。
- **逐条结果：** 点击前空闲 1.5 秒，`readNext` 与产出均为 0；一次点击只读一批 20 条；额外仅创建原 reader 后没有触发读取。稳定的一轮为 20/20/20/20/20/8，共 108 个唯一选择器、100 个网格元素，零重复，第 6 批 `done=true`；结束后不自动重扫，切换 Move→Inspect 后首批重新开始。隐藏、aria-hidden、inert、透明和离屏样本均被排除，溢出到视口的后代保留，边界元素的可见交集为 (0,90,60,42)。同源/跨源 iframe 仅返回两条边界，无内部条目或 src 泄露。剪贴板只注入一次拒绝；重试输入文本哈希完全相同、`readNext` 增量为 0，原生系统剪贴板读回的完整 JSON 一致（Windows 将换行规范化为 CRLF）。
